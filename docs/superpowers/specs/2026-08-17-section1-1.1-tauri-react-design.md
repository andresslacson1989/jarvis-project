## Goal

Establish a real, production-shaped JARVIS desktop workspace consisting of a Tauri 2 / Rust host and a React + TypeScript renderer whose production WebView loads only bundled local application assets. The subsection proves the executable desktop foundation without implementing later Phase 1 authority, platform-backend, Core-launch, security-policy, or full Mission Control responsibilities.

## Windows V1 qualification interpretation

For Section 1.1, the application/native **host** is the active Release Profile host: `WINDOWS + FULL_HOST + x64`. Mandatory Tauri/Rust application qualification therefore runs on native Windows using the pinned MSVC target. Future Linux portability is proven by semantic platform contracts, composition/import-boundary checks, and fail-closed platform-capability tests. Linux/Ubuntu Tauri host compilation, WebKitGTK/GTK host prerequisites, and Linux-to-MSVC cross-compilation are not Section 1.1 acceptance requirements and SHALL NOT be introduced as substitutes for native Windows proof.

## Architecture

```text
apps/desktop React + TypeScript source
        ↓ production web build
bundled local renderer assets
        ↓
Tauri 2 / Rust desktop host
        ↓ native qualification
Windows V1 FULL_HOST / x64 / MSVC
```

The renderer SHALL NOT connect to Core, spawn processes, hold credentials, authorize actions, or own consequential state. For 1.1, the preferred native command surface is no consequential custom command surface at all.

Development MAY use a local dev server through Tauri development configuration. Production SHALL use compiled local assets and SHALL NOT depend on a hosted application, CDN JavaScript, localhost production server, or arbitrary remote origin.

## UI shape for 1.1

Use a deliberately minimal inert JARVIS foundation screen sufficient to prove React renders inside the Tauri WebView. It may identify the product and truthful foundation state but SHALL NOT implement the full Mission Control shell or falsely imply that Core, providers, permissions, systems, or operational features are ready.

## Dependency and supply-chain rules

- Pin exact versions; do not use floating ranges.
- Preserve pnpm frozen-lockfile behavior, no lifecycle-script execution during CI install, strict peer dependency handling, and current workspace hardening.
- Record source/version/license/provenance for direct and relevant transitive dependencies according to existing repository checks.
- Do not broaden `allowBuilds` unless a concretely required dependency needs a lifecycle build and that behavior is reviewed and justified.
- Update the toolchain Tauri qualification marker only to the truthful state proven by this subsection. Do not imply Phase 1 release qualification beyond 1.1.

## Hard acceptance criteria

1. `apps/desktop` contains a real React + TypeScript application build.
2. `apps/desktop/src-tauri` contains a real Tauri 2 Rust host using exact selected Tauri versions.
3. `pnpm build:ui` produces the real renderer production bundle rather than declaration-only output.
4. Tauri production configuration references the local renderer build directory.
5. No production remote application URL or CDN executable dependency exists in the privileged renderer path.
6. The Tauri/Rust workspace compiles on native Windows for the active `WINDOWS + FULL_HOST + x64` target under the repository's pinned toolchain, including explicit `x86_64-pc-windows-msvc` Tauri compilation. Linux Tauri host compilation is not required or accepted as substitute evidence.
7. Static architecture checks remain green and no new native/backend leakage is introduced into shared Core/domain packages.
8. Exact dependency/provenance/license checks pass.
9. Regression tests fail if the production Tauri asset target stops being bundled-local, if selected Tauri pins drift, if mandatory CI drifts away from native Windows, if Linux Tauri host prerequisites are reintroduced, if tracked source is rewritten to make CI pass, or if required 1.1 CI/build gates are removed.
10. Full repository static CI passes on the exact candidate SHA with its mandatory jobs on native Windows.
11. `Contract Accuracy = 10/10`; all other applicable subsection scores meet the repository thresholds before `1.1` can be marked `VERIFIED`.
12. Candidate integration follows current compensating controls: temporary branch, exact candidate CI, independent review, immediate live-master revalidation, non-force integration, and authoritative post-integration verification.

## Test strategy

- add failing CI/checker mutations for Windows-runner drift, Linux Tauri host prerequisites, source-rewrite normalization, clean-checkout line-ending policy, and Tauri context-generation pairing;
- implement the minimum workspace/CI correction necessary to make those tests pass;
- run repository format/schema/contract/provenance/architecture/test/build/Rust gates on the Windows V1 qualification runner;
- prove native Windows `x86_64-pc-windows-msvc` compilation, including the explicit desktop Tauri gate;
- retain Linux portability proof only through platform architecture/import/capability tests;
- run exact-SHA GitHub `static-ci` before review/integration.

## Atomicity / idempotency / recovery

Repository implementation is performed as scoped commits on a temporary branch. Generated outputs SHALL be reproducible; repository-owned checkout attributes SHALL make a clean Windows checkout acceptable without ad-hoc rewriting of tracked source. Repeated builds/checks SHALL not mutate authoritative source state. Failed builds or tests leave the candidate unqualified and do not advance the live matrix to `VERIFIED`. Integration remains a separate non-force ref operation after exact candidate qualification and independent review.

## Completion boundary

A successful 1.1 result proves only that the real Tauri/React bundled-local desktop workspace exists, builds natively on the Windows V1 target, and is contract-shaped for later hardening. It does not prove the later WebView security policy, Windows platform backends, Core runtime ownership, full Mission Control product behavior, or any Linux runtime support.
