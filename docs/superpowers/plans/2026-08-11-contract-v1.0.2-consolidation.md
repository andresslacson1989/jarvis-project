# JARVIS Contract v1.0.2 Consolidation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the competing/superseding JARVIS contract layers with one contradiction-free v1.0.2 canonical suite while preserving every still-valid production decision.

**Architecture:** Use `codex/contract-consistency-fixes` as the latest semantic lineage and import useful implementation-lock material as contract content rather than duplicate ADR identities. Make the top-level v1.0.2 contract and its current appendices self-contained; ADRs become rationale/history and future ADR changes must update affected canonical documents synchronously.

**Tech Stack:** Markdown architecture contracts, Git/GitHub branch history, Tauri 2/Rust/React/Node/TypeScript/SQLite/SQLCipher/Codex/Proxmox design constraints.

## Global Constraints

- Preserve Tauri 2 + React UI, Rust native host, separate Node/TypeScript Core, SQLite/SQLCipher, provider abstraction, graph workers, and local-first voice architecture unless a real production blocker is found.
- Preserve `AI decides. Software authorizes. Software verifies.`
- Preserve mandatory final confirmation for destructive/materially unrecoverable actions.
- Preserve ADR-057 through ADR-068 semantics unless this consolidation makes a stricter compatible rule explicit.
- V1 mandatory integrations remain Local filesystem/Git, GitHub, Codex/OpenAI, and Proxmox VE.
- Voice remains a V1 production requirement.
- SSH, Google Workspace, Microsoft 365, and Cloudflare remain mandatory for the first feature-bearing post-V1 release.
- Do not import duplicate ADR-054/055/056 identities from `codex/contract-implementation-lock`.
- No active normative file may require readers to overlay stale documents to know current behavior.
