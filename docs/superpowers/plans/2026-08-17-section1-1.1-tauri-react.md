# Section 1.1 Tauri + React Desktop Foundation Implementation Plan

> **For agentic workers:** use test-driven-development before implementation and verification-before-completion before any completion claim.

**Goal:** Implement subsection 1.1 as a real Tauri 2 / Rust + React / TypeScript desktop workspace whose production WebView consumes bundled local renderer assets, while preserving the authority boundaries and leaving all 1.2+ responsibilities unclaimed.

**Architecture:** `apps/desktop` is the real Vite/React frontend; `apps/desktop/src-tauri` is the minimal Rust/Tauri host. Production `frontendDist` is local `../dist`. The renderer has no Core connection, provider/process execution, credential access, filesystem/shell authority, or consequential Tauri command surface.

**Pinned stack:** Node 24.18.0; pnpm 11.21.0; TypeScript 6.0.3; Rust 1.97.1; target `x86_64-pc-windows-msvc`; Tauri 2.11.5; tauri-build 2.6.3; @tauri-apps/api 2.11.1; @tauri-apps/cli 2.11.4; React/react-dom 19.2.8; Vite 8.1.5; @vitejs/plugin-react 6.0.3.

## Windows V1 qualification rule

For Section 1.1 the application/native host is the active Release Profile host: `WINDOWS + FULL_HOST + x64`. Native Tauri qualification runs on `windows-2025` using the pinned MSVC target. Linux portability remains an architecture/import/platform-capability property; Linux/Ubuntu Tauri host compilation, WebKitGTK/GTK prerequisites, and Linux-to-MSVC cross-builds are not Section 1.1 acceptance gates.

The native qualification job must keep ordinary workspace compilation separate from the actual production application proof:

```text
cargo check --locked --workspace --target x86_64-pc-windows-msvc
pnpm tauri build --no-bundle --target x86_64-pc-windows-msvc --ci
```

The second command runs from `apps/desktop`. It is the explicit production Tauri gate: Tauri must execute configured `beforeBuildCommand: pnpm build:web`, consume local `frontendDist: ../dist`, compile the optimized release application, and emit `jarvis-desktop.exe`. A `cargo check` must never be represented as that production proof.

1. Record the immutable functional implementation candidate and its exact native-production run in checked-in evidence.
