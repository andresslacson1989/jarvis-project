# ADR-036 — Validated Tool Execution Boundary

**Status:** Accepted  
**Date:** 2026-08-11

## Context

JARVIS uses AI to interpret user intent and propose actions. AI-generated tool names, targets, environments, paths, arguments, and execution parameters can still be incorrect even when the high-level intent is understood correctly. A production system must therefore prevent AI output from becoming trusted execution merely because it was generated by an approved model.

## Decision

JARVIS SHALL treat all AI-generated tool calls and arguments as untrusted execution proposals.

Before execution, tool requests MUST pass, as applicable:

1. schema validation;
2. contextual validation;
3. permission and risk evaluation;
4. target resolution;
5. precondition checks;
6. resource and policy checks.

Consequential or destructive actions SHOULD resolve vague or abstract references into explicit concrete targets before authorization or execution.

Tools SHOULD expose narrow structured operations rather than unrestricted command execution wherever practical. Broad shell or command execution MAY exist for approved engineering workers, but it SHALL live behind a stricter execution boundary and MUST NOT be the normal orchestrator control surface.

Successful invocation of a tool MUST NOT automatically be considered successful task completion. Important actions SHOULD perform postcondition verification against live state.

Invalid, ambiguous, contradictory, stale, or unauthorized tool arguments MUST be rejected, re-planned, or clarified rather than guessed.

The governing principle is:

> **AI decides. Software authorizes. Software verifies.**

## Consequences

- AI remains responsible for flexible interpretation and planning.
- JARVIS Core remains the execution authority.
- Tool schemas become an important security and correctness boundary.
- High-risk actions can present the resolved target to the user rather than repeating vague natural-language wording.
- Postcondition verification prevents a tool returning successfully from being mistaken for the requested real-world result.
- Narrow tools reduce the blast radius of hallucinated or malformed arguments.

## Relationship to Earlier Decisions

This decision extends the context-aware permission engine, provider isolation, context authority, task management, and the existing principle that AI may decide but software must authorize execution.
