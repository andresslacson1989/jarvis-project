- `actions/checkout` v7.0.1 commit `3d3c42e5aac5ba805825da76410c181273ba90b1`
- `pnpm/setup` v2.0.2 commit `84cb39b217b10273981911c288cd62326dc7c6d2`

## TDD and adversarial verification

RED/GREEN work proved the checkers reject rather than merely inspect:

- CRLF, tabs, missing final newline, and trailing whitespace in controlled roots;
- malformed/wrong-draft/duplicate/escaping/unresolved schema references;
- private-key/token patterns, non-example `.env` files, and probable literal secrets while allowing explicit synthetic placeholders;
- non-exact installed npm dependency pins, unreviewed lock packages, and unreviewed Cargo packages;
- floating or unknown CI actions, installed license/version drift, and canonical toolchain drift;
- false commit-bound PASS evidence without the required GitHub metadata/gate flag;
- malformed Rust bootstrap syntax;
- clean-checkout absence of empty future test-layer directories.

Additional regression coverage proves peer-dependency compatibility ranges are not incorrectly treated as installed-version pins, and the format gate remains scoped away from normative contract Markdown.

## Failure / retry / idempotency properties

- All gates are deterministic repository checks or pinned build/test commands and are safe to repeat on the same checkout.
- CI does not auto-waive security failures or automatically rerun failed gates to manufacture green status.
- The two real CI defects were diagnosed from the exact failed step, fixed with regression coverage, and re-executed through a fresh commit/run.
- Final evidence is bound to a concrete commit/run and cannot be generated as PASS merely because a previous run succeeded.
- Build output is isolated under ignored `.artifacts/` and does not mutate authoritative source/configuration state.
