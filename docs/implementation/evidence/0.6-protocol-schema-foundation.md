- `ipc-envelope.schema.json`
- `ipc-response.schema.json`
- `session-state.schema.json`
- `user-instruction.schema.json`

Key fail-closed/bounded properties include:

- UUIDv7 version and RFC variant validation;
- UTC timestamp schema with Draft 2020-12 `date-time` plus terminal `Z` requirement;
- exact money nano-units represented as integer text rather than binary floating point;
- Argon2id production floors from the contract plus defensive parser/resource ceilings explicitly documented as bounds, not selected production profile constants;
- strict closed-object schemas for contract-defined records;
- explicit success/failure `IpcResponse` union with no ad-hoc status convention;
- event IPC envelopes require `id: null`, while request/response envelopes require UUIDv7 identity;
- generic JSON values bounded by collection size, property-name size, string size, numeric magnitude, and nesting depth;
- session/user-input schemas reject undeclared secret-bearing fields.

The runtime-validation interface explicitly requires concrete validators to assert declared formats, avoid coercion for security/exact-money fields, and emit bounded/secret-safe validation diagnostics.

## Atomicity / idempotency / failure model

Atomicity: **N/A**. This subsection introduces immutable protocol/schema definitions and pure validation contracts; it performs no authoritative state mutation or external consequential effect.

Idempotency/retry safety: schema validation is deterministic and side-effect free for the same schema/input pair. Re-validating an input does not mutate state or create external effects.

Failure/recovery: malformed, unknown-required, out-of-bound, unsupported-version, under-floor KDF metadata, and invalid union shapes fail validation closed. The validator contract does not authorize blind retry based on human error text or the `retryable` advisory field.
