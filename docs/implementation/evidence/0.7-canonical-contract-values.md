### Canonical values encoded

The machine-readable binding contains only values fixed by the current active suite, including:

- contract suite/profile/component revisions;
- protocol major `1`;
- Windows 11 25H2 `WINDOWS + FULL_HOST + x64` V1 target;
- modeled platform/runtime-role enums without Linux/Android support claims;
- the fifteen required configuration domains;
- provider setup states;
- module execution classes;
- exact mandatory/optional GitHub and Proxmox capability sets;
- Argon2id version/floors;
- `JARVIS_BACKUP_V1` cryptographic/bounds/recovery-slot constants;
- TUF 1.0.35 semantics, Ed25519 profile, threshold minima/fixed thresholds, consistent snapshots, and validity ceilings;
- approval-action canonicalization/digest constants.

The file intentionally omits dynamic release facts such as source commit, Node/Rust/TypeScript/Tauri/package-manager versions, signing identities, release sequence/security epoch, concrete provider versions, and TUF key IDs. Those remain release-manifest facts and would be false to invent during Phase 0.

### Semantics preserved

- Capability/platform/runtime arrays that are semantic sets use uniqueness/count/enum validation; array order is not promoted into a normative meaning.
- Configuration domains in the canonical binding require the fifteen current contract minima but permit future typed domains; the current V1 `ConfigurationDomain` schema enumerates the fifteen implemented domains.
- TUF snapshot/timestamp role values are modeled as `minimumThreshold`/`minimumKeyCount` because the contract permits `1-of-1 or stronger`; they are not falsely fixed to exactly one key forever.
- Bootstrap configuration is closed, versioned, Windows-V1-specific, requires the canonical-values identity, and rejects extra/raw-secret fields.
- `backendProfileId` remains a bounded runtime/release identity rather than being incorrectly elevated into a normative contract constant.
