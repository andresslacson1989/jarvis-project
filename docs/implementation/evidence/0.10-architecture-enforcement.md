## Enforcement behavior

The dependency-free checker scans production TypeScript/JavaScript/Rust source roots and enforces the Phase-0 architecture boundary:

- shared Core/domain/policy/protocol/schema/platform-contract packages cannot import Windows/Linux native backend namespaces;
- package-unit imports are converted into a deterministic graph and cycles fail closed;
- UI source cannot import Core/platform/provider/tool/policy authority namespaces directly;
- `packages/shared` cannot become a hidden domain/service/platform/tool dependency sink;
- OS selection patterns such as `process.platform`, Deno/Bun platform selection, and Rust `cfg(target_os)` are rejected outside explicit composition/platform/provider/tool/Tauri adapter roots;
- Rust `unsafe` is rejected outside the explicit Windows-native allowlist;
- even in the native allowlist, an unsafe construct requires a nearby `SAFETY:` justification;
- the current platform composition root must preserve explicit `UNAVAILABLE` + `PLATFORM_BACKEND_UNQUALIFIED` behavior rather than silently falling back;
- violations are deterministically sorted and cause nonzero CLI exit.

The checker deliberately does not claim the later native Windows gates have already been implemented. Final Win32/Job Object/named-pipe/Tauri/backend qualification remains owned by its later feature and release rows.

## Atomicity / idempotency / failure model

Atomicity: **N/A**. The checker is a pure repository-analysis gate and performs no product-state or external consequential mutation.

Idempotency/retry safety: unchanged repository/policy inputs produce the same sorted violation set. Retrying a failed check does not alter repository state or convert failure into success.

Failure/recovery: malformed policy version, architecture violation, cycle, unsafe containment failure, or missing explicit platform-failure behavior causes a stable nonzero check result. There is no warning-only or fallback mode.
